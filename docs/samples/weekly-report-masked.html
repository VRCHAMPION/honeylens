7. Defender takeaways

  • Password guessing is constant (1673 attempts; top usernames: root, admin, ubuntu). Disable SSH password login and use keys (PasswordAuthentication no), or at least fail2ban.
  • Attackers wrote their own key into authorized_keys. Monitor ~/.ssh/authorized_keys for changes (file integrity monitoring) and remove unknown keys.
  • Cryptominer behaviour seen (stratum URLs, huge pages, killing rival miners). Alert on sustained high CPU and block outbound mining-pool ports such as 3333/4444 at the firewall.
  • Attackers try to download tools with wget/curl/tftp right after login. Restrict outbound traffic from servers (egress filtering) so downloads fail.
  • Log and history wiping seen. Ship logs off the server in real time so a local wipe cannot erase evidence.
  • Persistence via cron/systemd. Review crontabs and new services after any suspected compromise.
  • Treat IOCs (Indicators of Compromise) from a honeypot as low-confidence: block-list them for a short time only, because the IPs often belong to hacked third-party machines.

8. Methodology and limitations

  • Data: Cowrie 3.1.1 SSH honeypot JSON logs, parsed by the HoneyLens pipeline into PostgreSQL. Times stored in UTC, shown in IST.
  • ATT&CK mapping: 60 regex rules against Enterprise ATT&CK v19.2. A regex match is evidence, not proof; obfuscated commands can be missed (false negatives) and harmless text can match (false positives).
  • Severity (0-100) and classes are transparent heuristics; each session stores the reasons for its score. Bot-vs-human uses command timing and needs at least 3 commands.
  • GeoIP/ASN: offline MMDB databases if installed; simulator IPs get deterministic demo values (private-use ASNs 64512+). Registration location is not attacker identity.
  • A honeypot only sees attackers who chose to connect to it. It does not measure attacks against other systems.
  • Week-over-week compares 7-day windows; small numbers swing a lot in percentage.
